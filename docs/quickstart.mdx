## Requirements

- A GitHub or Google login
- A Rust backend with a committed `Cargo.lock`
- A server that reads the `PORT` environment variable

## Create the project contract

From your backend directory:

```sh
tovuk init
```

This creates `tovuk.toml`.

For a new project, start from a template:

```sh
tovuk init my-app --template fullstack-rust-tanstack
cd my-app/web && bun install && cd ..
```

## Check locally

```sh
tovuk doctor --json
```

Fix the first failed check before deploying. Tovuk errors include
`agent_instruction`, so agents can make the exact code change and rerun doctor.

Preview one project locally:

```sh
tovuk preview api
tovuk preview web
```

## Deploy

```sh
tovuk deploy --wait --json
```

On first deploy, the CLI opens browser login for GitHub or Google, stores the
Tovuk session, then continues automatically. Tovuk builds the backend, verifies
health, and returns the deployment URL.

If the build fails, inspect the build logs:

```sh
tovuk logs --build <build_id> --json
```

Fix the first actionable error, rerun doctor, then redeploy.

## Full-stack repos

Put one `tovuk.toml` in each deployable app directory, then run one command from
the repo root:

```sh
tovuk deploy --database
```

Tovuk discovers every nested project contract, deploys Rust backends first,
deploys static frontends next, and requests managed Postgres for Rust backends.
If the frontend calls the backend from the browser, configure backend CORS for
the frontend origin or use a same-origin custom domain.
