## Requirements

- A GitHub or Google login
- A Rust worker with a committed `Cargo.lock`, or a full-stack service with a
  Rust worker root and frontend root
- A server process that reads the `PORT` environment variable

## Deploy flow

<Steps>
  <Step title="Create the project contract">
    From your worker directory:

    ```sh
    tovuk new
    ```

    This creates a starter `tovuk.toml` from the files already in the
    directory. Review `kind`, `[capabilities]`, and build commands before
    deploy. Tovuk deploys from `tovuk.toml`; the file scan used by `tovuk new`
    is scaffolding only.

    For a new project, start from a template:

    ```sh
    tovuk new hello-service --template fullstack-rust-tanstack
    cd hello-service/web
    bun install
    cd ..
    ```
  </Step>

  <Step title="Check locally">
    ```sh
    tovuk check --json
    ```

    Fix the first failed check before deploying. Tovuk errors include
    `agent_instruction`, so agents can make the exact code change and rerun
    check.

    Confirm account setup:

    ```sh
    tovuk account show --json
    tovuk account update --handle your-handle --display-name "Your Team" --json
    ```

    Dry-run the deploy before creating a build:

    ```sh
    tovuk deploy --dry-run --json
    ```

    Review warnings, enabled capabilities, `missingConfig`, `requiredFixes`,
    meters, limits, and `billingEstimate`.
  </Step>

  <Step title="Deploy">
    ```sh
    tovuk deploy --wait --json
    ```

    Inspect deploy state with `tovuk deploy list --json` or
    `tovuk deploy show <deploy_id> --json` when an agent needs to recover
    context. Cancel stale queued work with
    `tovuk deploy cancel <deploy_id> --json` when a newer deploy supersedes it.

    On first deploy, the CLI opens browser login for GitHub or Google, stores
    the Tovuk session, then continues automatically. Tovuk builds the worker,
    verifies health, and returns the deployment URL.

    If the build fails, inspect the build logs:

    ```sh
    tovuk logs --build <build_id> --json
    ```

    Fix the first actionable error, rerun check, then redeploy.
  </Step>

  <Step title="Use one root for full-stack repos">
    Put one `tovuk.toml` in the repo root, with explicit `[capabilities]`,
    `[worker]`, and `[frontend]` sections. Run one command from the repo root:

    ```sh
    tovuk deploy --wait --json
    ```

    Tovuk builds both roots, serves the frontend at `/`, and routes `/api/*` to
    the Rust worker on the same service URL.
  </Step>
</Steps>
