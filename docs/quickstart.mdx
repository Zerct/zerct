## Requirements

- A GitHub or Google login
- A Rust backend with a committed `Cargo.lock`
- A server that reads the `PORT` environment variable

## Create the project contract

From your backend directory:

```sh
npx @zerct/zerct init
```

This creates `zerct.toml`.

For a new project, start from a template:

```sh
npx @zerct/zerct init my-app --template fullstack-rust-tanstack
cd my-app/web && bun install && cd ..
```

## Check locally

```sh
npx @zerct/zerct doctor
```

Fix any reported issue before deploying. Zerct errors are written so agents can
read the `agent_instruction` field and retry.

Preview one project locally:

```sh
npx @zerct/zerct preview api
npx @zerct/zerct preview web
```

## Deploy

```sh
npx @zerct/zerct deploy
```

On first deploy, the CLI opens browser login for GitHub or Google, stores the
Zerct session, then continues automatically. Zerct builds the backend, verifies
health, and returns the deployment URL.

## Full-stack repos

Put one `zerct.toml` in each deployable app directory, then run one command from
the repo root:

```sh
npx @zerct/zerct deploy --database
```

Zerct discovers every nested project contract, deploys Rust backends first,
deploys static frontends next, and requests managed Postgres for Rust backends.
If the frontend calls the backend from the browser, configure backend CORS for
the frontend origin or use a same-origin custom domain.
