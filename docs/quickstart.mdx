description: "Deploy a Rust worker with Tovuk."
---

## Requirements

- A GitHub or Google login
- A Rust worker with a committed `Cargo.lock`
- A server that reads the `PORT` environment variable

## Create the project contract

From your worker directory:

```sh
tovuk new
```

This creates `tovuk.toml`.

For a new project, start from a template:

```sh
tovuk new hello-service --template worker-static-rust-tanstack
cd hello-service/web && bun install && cd ..
```

## Check locally

```sh
tovuk check --json
```

Fix the first failed check before deploying. Tovuk errors include
`agent_instruction`, so agents can make the exact code change and rerun check.

Dry-run the deploy before creating a build:

```sh
tovuk deploy --dry-run --json
```

Review warnings, enabled capabilities, meters, limits, and `billingEstimate`.

## Deploy

```sh
tovuk deploy --wait --json
```

On first deploy, the CLI opens browser login for GitHub or Google, stores the
Tovuk session, then continues automatically. Tovuk builds the worker, verifies
health, and returns the deployment URL.

If the build fails, inspect the build logs:

```sh
tovuk logs --build <build_id> --json
```

Fix the first actionable error, rerun check, then redeploy.

## Worker-static repos

Put one `tovuk.toml` in the repo root, with explicit `[capabilities]`,
`[worker]`, and `[frontend]` sections. Run one command from the repo root:

```sh
tovuk deploy --wait --json
```

Tovuk builds both roots, serves the frontend at `/`, and routes `/api/*` to the
Rust worker on the same service URL.
