---
title: "Object Storage"
description: "Agent-ready service files and media storage."
---

Tovuk object storage is scoped to a service and is available through the native
CLI, SDK-compatible HTTP API, and presigned upload/download URLs. Agents should
prefer JSON output so paths, public URLs, byte counts, and error recovery
instructions can be parsed without dashboard access.

The storage origin is private and S3-compatible. Agents and users should use
Tovuk API and CLI commands instead of provider bucket URLs.

## CLI

```sh
tovuk storage list --service service_1 --json
tovuk storage upload --service service_1 ./logo.png uploads/logo.png --public --json
tovuk storage download --service service_1 uploads/logo.png ./logo.png --json
tovuk storage url --service service_1 uploads/logo.png --json
tovuk storage delete --service service_1 uploads/logo.png --json
```

`tovuk files` and `tovuk media` are aliases for the same command group. Omit
`--public` for private files. Use `--content-type <mime>` when the CLI cannot
infer the media type from the extension.

Public files return a public media URL on `media.tovuk.app`. Private files use
short-lived download URLs.

## Limits

Free plan:

- 10 GB total object storage
- no object-count cap
- 5 TiB object storage maximum object size
- 5120 MiB (5 GiB) per single-part object upload
- 4.995 TiB per multipart object upload when multipart upload support is exposed
- 10 thousand multipart upload parts when multipart upload support is exposed
- 1 million Class A operations per month
- 10 million Class B operations per month

Pro plan:

- no storage or object-count hard cap, with 10 GB included before paid storage
  overage
- 5 TiB object storage maximum object size
- 5120 MiB (5 GiB) per single-part object upload
- 4.995 TiB per multipart object upload when multipart upload support is exposed
- 10 thousand multipart upload parts when multipart upload support is exposed
- 1 million Class A operations per month included, then paid overage
- 10 million Class B operations per month included, then paid overage
- free egress and free delete operations

Use Class A caps for write/list-heavy workflows and Class B caps for
read/download-heavy workflows. Use `object_storage_bytes` to cap total stored
bytes across the account:

```sh
tovuk limit set object_storage_bytes --period month --value 10000000000 --json
tovuk limit set object_storage_class_a_operations --period month --value 1000000 --json
tovuk limit set object_storage_class_b_operations --period month --value 10000000 --json
```

Upload URL creation reserves the requested bytes before returning the presigned
URL. Agents should call `tovuk storage delete --service <service> <path> --json`
to release a pending upload reservation when an upload is abandoned.

Check the live storage prices and included usage before heavy media work:

```sh
tovuk pricing --json
```

When a storage limit blocks work, run:

```sh
tovuk billing checkout "Object storage limit reached" --json
```

Show the returned Checkout URL to the user. If the command fails for a platform
reason after retrying, create a support ticket with the service id, storage path,
failed command, and first actionable error.
