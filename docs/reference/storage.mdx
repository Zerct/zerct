---
title: "Object Storage"
description: "Agent-ready service files and media storage."
---

Tovuk object storage is scoped to a service and is available through the native
CLI, SDK-compatible HTTP API, and presigned upload/download URLs. Agents should
prefer JSON output so paths, public URLs, byte counts, and error recovery
instructions can be parsed without dashboard access.

The storage origin is private and S3-compatible. Agents and users should use
Tovuk API and CLI commands instead of provider bucket URLs.

## Dashboard

Dashboard Storage is available at `https://tovuk.com/account/storage` and
`https://tovuk.com/<handle>/storage`. It lists objects, uploads ordinary files,
automatically uses multipart transfer for files larger than 100 MiB, creates
download URLs, and deletes objects through the same API routes and limits as the
CLI.

The dashboard uses these storage API routes:

- `GET /v1/services/{service_id}/storage`
- `POST /v1/services/{service_id}/storage/upload-url`
- `POST /v1/services/{service_id}/storage/complete`
- `POST /v1/services/{service_id}/storage/multipart/create`
- `POST /v1/services/{service_id}/storage/multipart/complete`
- `POST /v1/services/{service_id}/storage/multipart/abort`
- `POST /v1/services/{service_id}/storage/download-url`
- `DELETE /v1/services/{service_id}/storage?path=<path>`

Use `tovuk storage upload --json` when an agent needs local-file automation
outside the browser. The CLI and dashboard both handle multipart upload and
recovery without manual presigned URL handling.

## CLI

```sh
tovuk storage list --service service_1 --json
tovuk storage upload --service service_1 ./logo.png uploads/logo.png --public --json
tovuk storage download --service service_1 uploads/logo.png ./logo.png --json
tovuk storage url --service service_1 uploads/logo.png --json
tovuk storage delete --service service_1 uploads/logo.png --json
```

Omit `--public` for private files. Use `--content-type <mime>` when the CLI
cannot infer the media type from the extension.

`tovuk storage upload` automatically uses single-part upload for ordinary files
and multipart upload for files larger than 100 MiB. Agents do not need a
dashboard step or manual presigned URL handling for large media.

Public files return a public media URL on `media.tovuk.app`. Private files use
short-lived download URLs.

Public media uploads are scanned at upload URL creation and again at completion.
Public objects reject executable and script content types or extensions such as
`.exe`, `.sh`, `.js`, `.wasm`, and `.jar`. Store artifacts privately, and use
Static Frontend for browser-executed web assets.

## Direct Multipart API

Agents should prefer the CLI. Use the multipart HTTP flow only when custom
transfer control is required:

1. `POST /v1/services/{service_id}/storage/multipart/create` with `path`,
   `contentType`, `sizeBytes`, optional `partSizeBytes`, and `publicRead`.
2. Upload each returned part URL with `PUT` and keep its `ETag` header.
3. `POST /v1/services/{service_id}/storage/multipart/complete` with `path`,
   `uploadId`, and completed part numbers plus ETags.
4. `POST /v1/services/{service_id}/storage/multipart/abort` after a failed
   upload attempt so pending byte reservations are released.

## Limits

Free plan:

- 10 GB total object storage
- no object-count cap
- 5,237,760 MiB (`4.995 TiB`) object storage maximum object size
- 5,115 MiB (`4.995 GiB`) per single-part object upload
- 5,237,760 MiB (`4.995 TiB`) per multipart object upload
- 10 thousand multipart upload parts
- 1 million Class A operations per month
- 10 million Class B operations per month
- 1 TB object storage egress per month
- free delete operations
- 50 custom domains per storage bucket
- 50 bucket management operations per second
- 1 write per second to the same object key

Pro plan:

- no storage or object-count hard cap, with 10 GB included before paid storage
  overage
- 5,237,760 MiB (`4.995 TiB`) object storage maximum object size
- 5,115 MiB (`4.995 GiB`) per single-part object upload
- 5,237,760 MiB (`4.995 TiB`) per multipart object upload
- 10 thousand multipart upload parts
- 1 million Class A operations per month included, then paid overage
- 10 million Class B operations per month included, then paid overage
- 1 TB object storage egress per month included, then paid egress overage
- free delete operations
- same object size, multipart, custom-domain, bucket-management, and same-key
  write limits as Free

Use Class A caps for write/list-heavy workflows and Class B caps for
read/download-heavy workflows. Multipart upload create consumes Class A
operations for create and every part upload URL; multipart complete consumes
the completion Class A operation; multipart abort is free. Use
`object_storage_bytes` to cap total stored bytes across the account:

```sh
tovuk limits set object_storage_bytes --period month --value 10000000000 --notify-at-percent 80 --json
tovuk limits set object_storage_class_a_operations --period month --value 1000000 --notify-at-percent 80 --json
tovuk limits set object_storage_class_b_operations --period month --value 10000000 --notify-at-percent 80 --json
tovuk limits set object_storage_egress_bytes --period month --value 1000000000000 --notify-at-percent 80 --json
```

Upload URL creation reserves the requested bytes before returning the presigned
URL. Agents should call `tovuk storage delete --service <service> <path> --json`
to release a pending upload reservation when an upload is abandoned.

Check the live storage prices and included usage before heavy media work:

```sh
tovuk pricing --json
tovuk usage --json
```

Use `billingEstimate.lineItems` for `object_storage_bytes`,
`object_storage_class_a_operations`, `object_storage_class_b_operations`, and
`object_storage_egress_bytes` before starting large uploads or public media
load tests.

When a storage limit blocks work, run:

```sh
tovuk billing checkout "Object storage limit reached" --json
```

Show the returned Checkout URL to the user. If the command fails for a service
reason after retrying, create a support ticket with the service id, storage path,
failed command, and first actionable error.
