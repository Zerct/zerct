Usage Caps stop activity at a configured meter threshold. Agents should set caps
before load tests, media uploads, queue fan-out, and paid usage.

## Cap-setting workflow

<Steps>
  <Step title="Read the meter catalog">
    ```sh
    tovuk pricing --json
    ```

    Use `products[].meter_details` and `products[].limit_fields` to pick the
    meter, period, and cap command before traffic depends on a paid capability.
  </Step>

  <Step title="Confirm account setup">
    ```sh
    tovuk account show --json
    tovuk account update --handle <handle> --display-name <name> --json
    ```

    Run the update command only when setup is incomplete. Usage, caps, and
    hosted billing links are account-scoped.
  </Step>

  <Step title="Dry-run the service plan">
    ```sh
    tovuk deploy --dry-run --json
    ```

    Compare the catalog with dry-run `meterPlan` entries, limits, usage, and
    `billingEstimate` before setting caps or creating a build.
  </Step>

  <Step title="Set caps before traffic">
    ```sh
    tovuk limits set worker_requests --period day --value 100000 --notify-at-percent 80 --json
    tovuk limits set object_storage_egress_bytes --period month --value 1000000000000 --notify-at-percent 80 --json
    ```

    Pass `--notify-at-percent <1-100>` to choose when Tovuk warns before a
    hard stop. If the flag is omitted, the CLI uses 80 percent.
  </Step>

  <Step title="Watch usage during tests">
    ```sh
    tovuk usage --json
    ```

    Compare current `usage`, configured caps, and `billingEstimate.lineItems`
    before load tests, backfills, and media imports continue.
  </Step>

  <Step title="Open billing deliberately">
    ```sh
    tovuk billing checkout --json
    tovuk billing portal
    ```

    Show the hosted checkout URL only when a human chooses higher paid
    capacity. Use the billing portal for invoices, payment methods, and
    subscription changes.
  </Step>

  <Step title="Remove stale caps">
    ```sh
    tovuk limits delete worker_requests --period day --json
    ```

    Delete a cap only after confirming replacement limits or accepted paid
    capacity.
  </Step>
</Steps>

## Dashboard

The dashboard Usage view is available at `https://tovuk.com/account/usage` or
`https://tovuk.com/<handle>/usage`. It includes the same hard-cap action as
`tovuk limits set` and the same removal action as `tovuk limits delete`, backed
by the same API routes and rate limits as the CLI. It shows copyable `tovuk limits set` commands with `--notify-at-percent` and copyable `tovuk limits delete` commands for the selected meter. It also opens the same hosted checkout flow as `tovuk billing checkout --json` for upgrades and the same hosted billing portal flow as `tovuk billing portal` for invoices, payment methods, and subscription changes.

## Agent commands

```sh
tovuk pricing --json
tovuk account show --json
tovuk deploy --dry-run --json
tovuk usage --json
tovuk limits set worker_requests --period day --value 100000 --notify-at-percent 80 --json
tovuk limits set worker_cpu_ms --period day --value 1000000 --notify-at-percent 80 --json
tovuk limits set object_storage_egress_bytes --period month --value 1000000000000 --notify-at-percent 80 --json
tovuk limits delete worker_requests --period day --json
```

## Usage Caps API

- `GET /v1/usage`
- `PUT /v1/usage/caps/{metric}` sets or replaces one cap. Send `period`, `capValue`, `hardStop`, and `notifyAtPercent`; the CLI sends `hardStop: true` and defaults `notifyAtPercent` to `80`.
- `DELETE /v1/usage/caps/{metric}/{period}` removes one cap for the selected `day` or `month` period.
