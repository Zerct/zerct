Tovuk keeps deploys predictable by rejecting projects that are expensive or
ambiguous to run.

## Current guardrails

- `Cargo.lock` is required.
- Rust workers run locked release-mode `cargo check`, locked release-mode
  tests, and strict all-target, all-feature Clippy with panic/unwrap bans and
  resource-sensitive lints.
- Deploy archives must contain source files only. Tovuk rejects generated
  directories, secret files, and compiled artifacts such as `.exe`, `.so`,
  `.dylib`, `.jar`, `.node`, and `.rlib`.
- Runtime memory is fixed at `128mb` for Tovuk workers.
- Runtime CPU allocation is fixed at `1`; usage is controlled by metered
  `worker_cpu_ms` caps.
- One service can bind up to 5000 service resources, including SQLite
  databases, KV namespaces, queues, State namespaces, and private
  service bindings.
- Service binding call chains can use up to 32 worker invocations per
  top-level request. Each service binding call also counts against the Worker
  subrequest limit.
- Rust worker artifacts are capped at 64 MiB before compression, 3 MiB after
  compression on Free, and 10 MiB after compression on Pro.
- Runtime idle timeout must be between `1` and `60` minutes.
- Static assets follow Tovuk limits: Free allows 20 thousand files
  per deployed version, Pro allows 100 thousand files per deployed version, and
  every individual static asset is capped at 25 MiB.
- Static responses meter `static_transfer_bytes`; Rust worker responses and
  WebSocket response-side tunnel bytes meter `worker_transfer_bytes`. Tovuk
  does not set a default plan transfer cap. Agents should set explicit hard
  caps before high-throughput launches. Both meters appear in
  `usage.billingEstimate.lineItems` with `free_transfer` billing units, null
  prices, and zero estimated cost.
- Static output rejects symlinks and non-file, non-directory entries.
- `_headers` supports up to 100 header rules with 2000 characters per line.
- `_redirects` supports up to 2000 static redirects, 100 dynamic redirects,
  2100 total redirects, and 1000 characters per rule.
- Package static frontend projects run stable native type-aware TypeScript
  checks and native linting before build work starts.
- Package frontend browser source must use `.ts` or `.tsx`; `.js`, `.jsx`,
  `.mjs`, and `.cjs` browser source is rejected. Plain static HTML/CSS/JS
  frontends without `package.json` may use no-op build commands.
- A health endpoint is required for Rust workers.
- Rust workers must bind to `0.0.0.0:$PORT`.
- Secrets must stay in server-side environment variables.
- Builds may be queued when capacity is busy.
- Builds run with 2 vCPU on Free, 4 vCPU on Pro, 8 GB memory, 20 GB disk,
  20 minute max duration, 64 build environment variables, and a 5 KB limit per
  build environment variable. Deploy hooks can trigger 10 builds per service
  per minute and 100 builds per account per minute.
- Free service object storage includes 10 GB total, no object-count cap, a
  5,237,760 MiB (`4.995 TiB`) object storage object size ceiling, a
  5,115 MiB (`4.995 GiB`) single-part upload limit, a 5,237,760 MiB
  (`4.995 TiB`) multipart upload limit, 10 thousand
  multipart upload parts, 1 million Class A operations per month, 10 million
  Class B operations per month, 1 TB object storage egress per month, free
  delete operations, 50 custom domains per storage bucket, 50 bucket management
  operations per second, and 1 write per second to the same object key.
- Pro service object storage has no storage or object-count hard cap, includes
  10 GB, has the same 5,237,760 MiB object ceiling, 5,115 MiB
  single-part upload limit, and 5,237,760 MiB multipart upload limit, includes
  1 million Class A operations and 10 million Class B operations per month,
  includes 1 TB object storage egress per month, keeps deletes free, and
  exposes object storage paid overage rates in `tovuk pricing --json`.
- `tovuk storage upload` automatically switches to multipart upload above
  100 MiB and plans upload parts before transfer so agents can fail early on
  byte or operation caps.
- Public media uploads are scanned and reject executable or script payloads.
  Agents should store artifacts privately and use Static Frontend for web
  assets that browsers execute.
- Object storage upload URL creation reserves requested bytes until the object
  is completed or deleted, so agents can avoid concurrent upload overages
  without dashboard cleanup.
- Free worker requests: 100 thousand per day.
- Free SQLite databases: 10, with 5 GB total storage and 500 MB per database.
- Pro SQLite databases: 50 thousand, with a 1 TB account hard cap and 10 GB
  per database. The first 25 billion rows read, 50 million rows written, and
  5 GB storage are included each month before paid overage pricing.
- SQLite follows Tovuk limits for 30 second query timeouts, 50 queries per Worker
  invocation on Free, 1000 on Pro, 100 bound parameters, 100 KB SQL statements,
  100 columns, and 2 MB row/blob/string values.
- SQLite backups keep a 7 day restore window on Free and 30 days on Pro, with
  10 restores per database per 10 minute window.
- Free KV meters: 100 thousand reads per day, 1000 writes per day, 1000
  deletes per day, 1000 lists per day, and 1 GB storage per account and
  namespace.
- Pro KV has no account or namespace storage hard cap. The first 10 million
  reads, 1 million writes, 1 million deletes, 1 million lists, and 1 GB
  storage are included each month before paid overage pricing.
- KV metadata is limited to 1024 bytes. KV `expirationTtlSeconds` must be at
  least 30 seconds, and KV `expiration` must be at least 30 seconds in the
  future. KV keys are limited to 512 bytes and values to 25 MiB.
- KV key list pages default to 1000 keys and accept limits from 10 to 1000.
- Bulk KV reads accept up to 100 keys per request. Bulk KV writes and deletes
  accept up to 10000 keys per request. KV bulk request bodies must fit 100 MB.
- Free queue operations: 10 thousand per day, counted per 64 KB read, write,
  or delete chunk.
- Pro queue operations: 1 million per month included before paid overage
  pricing.
- Queue messages are limited to 128 KB total. Tovuk reserves 100 bytes for
  Tovuk queue metadata, so the maximum user body is 127900 bytes.
  Send delay is limited to 24 hours, retries are limited to 100, batches can
  contain up to 100 messages, and one send batch is capped at 256 KB total.
- Queue consumer batch size defaults to 10 and can be configured from 1 to
  100. Batch timeout defaults to 5 seconds and can be configured from 0 to
  60 seconds.
- Free queue retention is fixed at 24 hours. Pro queue retention defaults to
  4 days and can be configured up to 14 days.
- Queue deliveries are sent to `POST /.tovuk/queues/<queue>` in batches of up
  to the queue's configured batch size. Failed messages can be routed to a
  configured dead-letter queue after retries are exhausted. Queue handlers have
  a `15 minute` wall-clock limit.
- Cron deliveries are sent to `POST /.tovuk/cron/<trigger>` after Tovuk wakes
  the Rust worker if needed. Cron handlers have a `15 minute` wall-clock limit.
- State SQLite storage is 1 GB per object on Free and 10 GB per object on Pro,
  with a 5 GB Free account storage cap, 5 million SQLite rows read per day,
  and 100 thousand SQLite rows written per day. Pro includes 1 million
  requests, 400 thousand GB-s duration, 25 billion SQLite rows read, and
  50 million SQLite rows written per month before paid overage pricing.
- State alarms allow one scheduled alarm per State object. A replaced alarm
  keeps only the newest schedule. Failed alarm handlers retry at least once with
  exponential backoff starting at 2 seconds and stop after 6 retries. State
  alarm handlers have a `15 minute` wall-clock limit.
- State key and value payloads are limited to 2 MiB combined.
- Free logs include 200 thousand events per day with 3 day retention. Pro logs
  include 20 million events per month with 7 day retention. Each captured log
  event is capped at 256 KB.
- Free support tickets: 3 per day.
- Pro support tickets: 20 per day.
- Free API tokens: 10.
- Pro API tokens: 100.

## Plan limit recovery

When a free-tier account reaches a plan limit, recover in this order so
account-scoped actions have the right context:

<Steps>
  <Step title="Confirm account setup">
    Billing checkout, usage, and cap changes are account-scoped. Check the
    account first, then run the update command only when setup is incomplete.

    ```sh
    tovuk account show --json
    tovuk account update --handle <handle> --display-name <name> --json
    ```
  </Step>

  <Step title="Check current usage">
    Compare current usage, plan limits, billing estimates, and existing caps
    before creating checkout links or changing hard caps.

    ```sh
    tovuk usage --json
    ```
  </Step>

  <Step title="Create checkout when payment is the blocker">
    If the limit requires a plan change or paid usage, create a hosted
    subscription link and show the returned `checkout.url` to the human.

    ```sh
    tovuk billing checkout "Plan limit reached" --json
    ```
  </Step>

  <Step title="Escalate non-payment blockers">
    If usage and checkout do not explain the blocker, create a support ticket
    with command output and ids. Resolve the ticket after the issue is fixed.

    ```sh
    tovuk support create "Limit issue" "Agent could not proceed after checking usage." --service service_1 --build job_1 --deploy deploy_1 --failing-command "tovuk deploy --wait --json" --first-log-line "plan limit reached" --json
    tovuk support resolve ticket_0123456789abcdef0123 --json
    ```
  </Step>
</Steps>

## Paid usage caps

Pro included monthly usage is billing metadata, not the default hard stop.
Agents should set explicit hard caps before high-throughput tests or launch:

Supported cap meters are `worker_requests`, `worker_cpu_ms`,
`worker_transfer_bytes`, `static_transfer_bytes`, `sqlite_rows_read`,
`sqlite_rows_written`, `sqlite_storage_bytes`, `kv_reads`, `kv_writes`,
`kv_deletes`, `kv_lists`, `kv_storage_bytes`, `queue_operations`,
`state_requests`, `state_duration_gb_milliseconds`, `state_sqlite_rows_read`,
`state_sqlite_rows_written`, `state_sqlite_storage_bytes`,
`object_storage_bytes`, `object_storage_class_a_operations`,
`object_storage_class_b_operations`, `object_storage_egress_bytes`,
`build_minutes`, and `log_events`.

```sh
tovuk account show --json
tovuk pricing --json
tovuk usage --json
tovuk limits set build_minutes --period month --value 6000 --notify-at-percent 80 --json
tovuk limits set worker_requests --period month --value 10000000 --notify-at-percent 80 --json
tovuk limits set worker_cpu_ms --period month --value 30000000 --notify-at-percent 80 --json
tovuk limits set static_transfer_bytes --period month --value 107374182400 --notify-at-percent 80 --json
tovuk limits set worker_transfer_bytes --period month --value 107374182400 --notify-at-percent 80 --json
tovuk limits set sqlite_rows_read --period month --value 25000000000 --notify-at-percent 80 --json
tovuk limits set sqlite_rows_written --period month --value 50000000 --notify-at-percent 80 --json
tovuk limits set sqlite_storage_bytes --period month --value 5000000000 --notify-at-percent 80 --json
tovuk limits set kv_reads --period month --value 10000000 --notify-at-percent 80 --json
tovuk limits set kv_writes --period month --value 1000000 --notify-at-percent 80 --json
tovuk limits set kv_deletes --period month --value 1000000 --notify-at-percent 80 --json
tovuk limits set kv_lists --period month --value 1000000 --notify-at-percent 80 --json
tovuk limits set kv_storage_bytes --period month --value 1000000000 --notify-at-percent 80 --json
tovuk limits set queue_operations --period month --value 1000000 --notify-at-percent 80 --json
tovuk limits set state_requests --period month --value 1000000 --notify-at-percent 80 --json
tovuk limits set state_duration_gb_milliseconds --period month --value 400000000 --notify-at-percent 80 --json
tovuk limits set state_sqlite_rows_read --period month --value 25000000000 --notify-at-percent 80 --json
tovuk limits set state_sqlite_rows_written --period month --value 50000000 --notify-at-percent 80 --json
tovuk limits set state_sqlite_storage_bytes --period month --value 5000000000 --notify-at-percent 80 --json
tovuk limits set object_storage_bytes --period month --value 10000000000 --notify-at-percent 80 --json
tovuk limits set object_storage_class_a_operations --period month --value 1000000 --notify-at-percent 80 --json
tovuk limits set object_storage_class_b_operations --period month --value 10000000 --notify-at-percent 80 --json
tovuk limits set object_storage_egress_bytes --period month --value 1000000000000 --notify-at-percent 80 --json
tovuk limits set log_events --period month --value 20000000 --notify-at-percent 80 --json
```
