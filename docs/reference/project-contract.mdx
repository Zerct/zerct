Tovuk deploys projects that are explicit and reproducible.

## Contract workflow

<Steps>
  <Step title="Choose the project kind">
    Pick one `kind` for the repo or service root:

    ```toml
    kind = "rust_worker"
    ```

    Use `rust_worker` for Rust APIs and event handlers, `static_frontend` for
    built static files, and `fullstack` when one root `tovuk.toml` builds both
    the frontend and Rust worker.
  </Step>

  <Step title="Declare capabilities explicitly">
    ```toml
    [capabilities]
    static_frontend = false
    worker = true
    sqlite = false
    object_storage = false
    kv = false
    state = false
    queue = false
    cron = false
    service_bindings = false
    secrets = false
    custom_domains = false
    logs = true
    builds = true
    usage_caps = true
    billing = true
    support = true
    abuse = true
    ```

    `static_frontend` and `worker` must match `kind`. `logs`, `builds`,
    `usage_caps`, `billing`, `support`, and `abuse` stay true because Tovuk
    exposes them for every service.
  </Step>

  <Step title="Check the contract locally">
    ```sh
    tovuk check --json
    ```

    Fix the first failed `agent_instruction`, then rerun `tovuk check --json`
    until the project contract and quality gates pass.
  </Step>

  <Step title="Dry-run with the intended account">
    ```sh
    tovuk account show --json
    tovuk account update --handle <handle> --display-name <name> --json
    tovuk deploy --dry-run --json
    ```

    Run the account update command only when setup is incomplete. Use the
    dry-run response to review enabled and disabled capabilities, missing
    config, meters, `meterPlan`, limits, and `billingEstimate` before deploying.
  </Step>
</Steps>

## Required files

Rust worker:

```txt
Cargo.toml
Cargo.lock
tovuk.toml
```

`Cargo.lock` is required so builds are deterministic.

Static frontend:

```txt
package.json
bun.lock or package-lock.json
src/main.tsx
tovuk.toml
```

Static frontend `package.json` must include `typecheck`, `lint`, and `build`
scripts. `typecheck` must run stable native type-aware TypeScript checks such
as `oxlint --type-aware --type-check`. `lint` must run native tooling such as
`oxlint` or `biome check`, plus Fallow `dead-code`, semantic
`dupes`, and `health` gates.

Plain static frontend:

```txt
index.html
tovuk.toml
```

Plain static frontends do not need a package manager. Use `check = ":"`,
`command = ":"`, and `output = "."`.

Full-stack service:

```txt
tovuk.toml
api/Cargo.toml
api/Cargo.lock
web/package.json or web/index.html
```

## Rust tovuk.toml

```toml
name = "hello-rust"
kind = "rust_worker"

[capabilities]
static_frontend = false
worker = true
sqlite = false
object_storage = false
kv = false
state = false
queue = false
cron = false
service_bindings = false
secrets = false
custom_domains = false
logs = true
builds = true
usage_caps = true
billing = true
support = true
abuse = true

[build]
check = "cargo fmt --all --check && cargo check --locked --release --all-targets --all-features && cargo test --locked --release --all-targets --all-features && cargo clippy --locked --release --all-targets --all-features -- -D warnings -D clippy::all -D clippy::pedantic -D clippy::dbg_macro -D clippy::todo -D clippy::unimplemented -D clippy::panic -D clippy::unwrap_used -D clippy::expect_used -D clippy::large_futures -D clippy::large_include_file -D clippy::large_stack_frames -D clippy::mem_forget -D clippy::rc_buffer -D clippy::rc_mutex -D clippy::redundant_clone -D clippy::clone_on_ref_ptr"
command = "cargo build --release"

[run]
command = "./target/release/hello-rust"
port = 3000
health = "/healthz"
```

## Frontend tovuk.toml

```toml
name = "marketing-site"
kind = "static_frontend"

[capabilities]

cron = false
service_bindings = false
secrets = false

abuse = true

[build]
check = "npm ci --prefer-offline --no-audit --fund=false && npm run typecheck && npm run lint"
command = "npm run build"
output = "dist"
```

## Full-stack tovuk.toml

```toml
name = "hello-service"
kind = "fullstack"

[capabilities]
static_frontend = true
worker = true
sqlite = false
object_storage = false
kv = false
state = false
queue = false
cron = false
service_bindings = false
secrets = false
custom_domains = false
logs = true
builds = true
usage_caps = true
billing = true
support = true
abuse = true

[worker]
root = "api"
check = "cargo fmt --all --check && cargo check --locked --release --all-targets --all-features && cargo test --locked --release --all-targets --all-features && cargo clippy --locked --release --all-targets --all-features -- -D warnings -D clippy::all -D clippy::pedantic -D clippy::dbg_macro -D clippy::todo -D clippy::unimplemented -D clippy::panic -D clippy::unwrap_used -D clippy::expect_used -D clippy::large_futures -D clippy::large_include_file -D clippy::large_stack_frames -D clippy::mem_forget -D clippy::rc_buffer -D clippy::rc_mutex -D clippy::redundant_clone -D clippy::clone_on_ref_ptr"
build = "cargo build --release"
command = "./target/release/api"
port = 3000
health = "/api/healthz"

[frontend]
root = "web"
check = "npm ci --prefer-offline --no-audit --fund=false && npm run typecheck && npm run lint"
build = "npm run build"
output = "dist"
```

## Rust runtime behavior

- Bind to `0.0.0.0:$PORT`
- Return success from the configured health path
- Keep secrets in server-side environment variables
- Avoid build steps that require interactive input

Static frontends do not run server code on Tovuk. Full-stack services keep the
frontend static and proxy `/api/*` to the Rust worker inside the same service URL.
JavaScript and TypeScript are frontend-only: Next API routes, Astro server
endpoints, Svelte `+server` handlers, middleware, SSR handlers, and Node/Bun
servers are rejected. Put that logic in Rust under the worker root.

Optional `_headers` and `_redirects` files belong in the built static output
root, not the source root unless the frontend build copies them there.
