Use this page when an AI coding agent is deploying with Tovuk.

## The loop

1. Run `tovuk doctor --json`.
2. If it fails, fix the first failed check by following `agent_instruction`.
3. Run `tovuk doctor --json` again.
4. Run `tovuk deploy --wait --json`.
5. If the build fails, run `tovuk logs --build <build_id> --json`.
6. Fix the first actionable error from the logs.
7. Redeploy with the same deploy command.
8. For service files or media, use `tovuk storage ... --json` instead of the
   dashboard.
9. For background work, create a queue and implement
   `POST /.tovuk/queues/<queue>` in the Rust worker.
10. For scheduled work, create a cron trigger and implement
   `POST /.tovuk/cron/<trigger>` in the Rust worker.
11. If a plan limit blocks the deploy or storage action, run
   `tovuk billing checkout --json` and show the returned
   `checkout.url` to the human.
12. If Tovuk itself needs help, create a support ticket with the exact command,
   service id, build id, deploy id, and first actionable log line.
13. Resolve the support ticket after the agent fixes the issue.

Do not weaken Rust lints, TypeScript strictness, stable native frontend
typechecking, native frontend linting, or unsafe restrictions to pass Tovuk
checks.
Do not create JavaScript or TypeScript servers. Keep JS/TS in static frontend
browser code only; move API routes, SSR handlers, middleware, and server logic
to Rust.

## Deploy prompt

```txt
Use Tovuk to deploy this project. Read https://docs.tovuk.com/llms.txt first.
Run `tovuk doctor --json`. Fix the first failed check by following
`agent_instruction`, then rerun doctor. Deploy with
`tovuk deploy --wait --json`. If the build fails, read
`tovuk logs --build <build_id> --json`, fix the first actionable
error, and redeploy. Use platform resource commands for SQLite, KV, queues,
cron triggers, Durable Objects, service bindings, and usage caps.
For queue handlers, implement `POST /.tovuk/queues/<queue>` and return `2xx`
only after the batch is safely handled. For cron handlers, implement
`POST /.tovuk/cron/<trigger>` and keep it idempotent.
```

## Support loop

Create support tickets only with enough evidence for a Tovuk support agent or
operator agent to act:

```sh
tovuk support create \
  "Deploy failed" \
  "Agent already ran doctor and retried deploy." \
  --service service_1 \
  --build job_1 \
  --deploy deploy_1 \
  --failing-command "tovuk deploy --wait --json" \
  --first-log-line "cargo check failed in src/main.rs" \
  --severity normal \
  --json
```

Before opening another ticket, list recent tickets:

```sh
tovuk support list --json
```

After the issue is fixed, resolve the ticket:

```sh
tovuk support resolve ticket_0123456789abcdef0123 --json
```

When a limit is the blocker, create a hosted Stripe subscription checkout link:

```sh
tovuk billing checkout "Project limit reached" --json
```

## Storage commands

```sh
tovuk storage list --service service_1 --json
tovuk storage upload --service service_1 ./logo.png uploads/logo.png --public --json
tovuk storage download --service service_1 uploads/logo.png ./logo.png --json
tovuk storage delete --service service_1 uploads/logo.png --json
```

Use `--public` only when the service needs a CDN URL. Use `--content-type <mime>`
when the extension is missing or ambiguous.

## Starter prompt

```txt
Create a Tovuk worker-static project. Run
`tovuk init hello-service --template worker-static-rust-tanstack`, then install
frontend packages in `hello-service/web`. Keep dynamic server logic in the Rust worker.
Keep the TanStack frontend static at runtime and call same-origin `/api`. Run
doctor in JSON mode, preview from the repo root when local tools are installed,
then deploy from the repo root.
```

## Log commands

```sh
tovuk service show service_1 --json
tovuk builds --service service_1 --json
tovuk logs --build job_1 --json
tovuk logs --deploy deploy_1 --json
tovuk logs --service service_1 --json
tovuk storage list --service service_1 --json
tovuk platform --service service_1 --json
tovuk database create --service service_1 DB --json
tovuk database query --service service_1 DB "select 1" --json
tovuk database delete --service service_1 DB --json
tovuk kv create --service service_1 CACHE --json
tovuk kv namespace delete --service service_1 CACHE --json
tovuk queue create --service service_1 jobs --json
tovuk queue delete --service service_1 jobs --json
tovuk cron create --service service_1 nightly "0 0 * * *" --json
tovuk durable-object create --service service_1 Room --json
tovuk binding create --service service_1 AUTH_SERVICE --target auth-service --json
tovuk limit set worker_requests --period day --value 100000 --json
tovuk billing checkout --json
tovuk support list --json
tovuk support resolve ticket_0123456789abcdef0123 --json
```

`logs --build` is the best first command after a failed deploy. Use
`logs --service` when you need the latest runtime and deploy context for one service.
