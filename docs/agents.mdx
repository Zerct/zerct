Use this page when an AI coding agent is deploying with Zerct.

## The loop

1. Run `npx @zerct/zerct doctor --json`.
2. If it fails, fix the first failed check by following `agent_instruction`.
3. Run `npx @zerct/zerct doctor --json` again.
4. Run `npx @zerct/zerct deploy --wait --json`.
5. If the build fails, run `npx @zerct/zerct logs --build <build_id> --json`.
6. Fix the first actionable error from the logs.
7. Redeploy with the same deploy command.
8. If a plan limit blocks the deploy, run
   `npx @zerct/zerct billing checkout --json` and show the returned
   `checkout.url` to the human.
9. If Zerct itself needs help, create a support ticket with the exact command,
   app id, build id, deploy id, and first actionable log line.
10. Resolve the support ticket after the agent fixes the issue.

Do not weaken Rust lints, TypeScript strictness, `tsgo --noEmit`, native
frontend linting, or unsafe restrictions to pass Zerct checks.

## Deploy prompt

```txt
Use Zerct to deploy this project. Read https://docs.zerct.com/llms.txt first.
Run `npx @zerct/zerct doctor --json`. Fix the first failed check by following
`agent_instruction`, then rerun doctor. Deploy with
`npx @zerct/zerct deploy --wait --json`. If the build fails, read
`npx @zerct/zerct logs --build <build_id> --json`, fix the first actionable
error, and redeploy. Use `--database` only when the Rust backend needs managed
Postgres.
```

## Support loop

Create support tickets only with enough evidence for a Zerct support agent or
operator agent to act:

```sh
npx @zerct/zerct support create \
  "Deploy failed" \
  "Agent already ran doctor and retried deploy." \
  --app app_1 \
  --build job_1 \
  --deploy deploy_1 \
  --failing-command "npx @zerct/zerct deploy --wait --json" \
  --first-log-line "cargo check failed in src/main.rs" \
  --severity normal \
  --json
```

Before opening another ticket, list recent tickets:

```sh
npx @zerct/zerct support list --json
```

After the issue is fixed, resolve the ticket:

```sh
npx @zerct/zerct support resolve ticket_0123456789abcdef0123 --json
```

When a limit is the blocker, create a hosted Stripe subscription checkout link:

```sh
npx @zerct/zerct billing checkout "Project limit reached" --json
```

## Starter prompt

```txt
Create a Zerct full-stack project. Run
`npx @zerct/zerct init my-app --template fullstack-rust-tanstack`, then install
frontend packages in `my-app/web`. Keep dynamic server logic in the Rust backend.
Keep the TanStack frontend static at runtime. Run doctor in JSON mode, preview
`api` and `web` when local tools are installed, then deploy from the repo root.
```

## Log commands

```sh
npx @zerct/zerct overview --app app_1 --json
npx @zerct/zerct builds --app app_1 --json
npx @zerct/zerct logs --build job_1 --json
npx @zerct/zerct logs --deploy deploy_1 --json
npx @zerct/zerct logs --app app_1 --json
npx @zerct/zerct billing checkout --json
npx @zerct/zerct support list --json
npx @zerct/zerct support resolve ticket_0123456789abcdef0123 --json
```

`logs --build` is the best first command after a failed deploy. Use
`logs --app` when you need the latest runtime and deploy context for one app.
