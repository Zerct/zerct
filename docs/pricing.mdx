Tovuk uses usage meters so agents can predict cost before they deploy. Free
plans hard-stop at the free limits. Pro costs `$5/month`, includes
the monthly allowances below, and lets agents set hard usage caps before paid
overages.

Use the CLI to read the live catalog:

```sh
tovuk pricing --json
```

The response includes both `plans` and `products`. Use `products[].meters` and
`products[].limit_fields` to choose the right product and set hard caps before
large deploys, media uploads, or paid usage.

Use the authenticated usage view before heavy work:

```sh
tovuk usage --json
```

`usage.billingEstimate` returns current-month line items for every priced
meter, including the usage amount, included amount, billable amount, billing
unit, rounding rule, and estimated USD micro-units. Storage estimates use the
current stored bytes as a full-month estimate so agents can plan conservatively.

## Free

- Projects: `100`.
- Rust Workers: `100,000` requests per day, `10 ms` CPU per invocation,
  `128 MiB` memory, `50` subrequests per request, `64 MiB` artifact size
  before compression, `3 MiB` compressed artifact size, and `5,000` resource
  bindings per service.
- Static assets: free and unlimited requests, free asset storage, `20,000`
  files per Worker version, `25 MiB` per file.
- Transfer: metered for visibility with no default plan cap. Agents can set
  `static_transfer_bytes` and `worker_transfer_bytes` hard caps before launch.
- SQLite: `10` databases, `5 GB` total, `500 MB` per database, `5 million`
  rows read per day, `100,000` rows written per day, and `7 days` of backups.
- KV: `1,000` namespaces, `1 GB` per account and namespace, `100,000`
  reads per day, `1,000` writes, deletes, and list requests per day.
- Queues: `10,000` queues, `10,000` operations per day, `128 KB` messages,
  `24 hour` retention, configurable batches, and dead-letter queues.
- State: `100` classes, `100,000` requests per day, `13,000 GB-s`
  duration per day, `5 million` SQLite rows read per day, `100,000` SQLite
  rows written per day, `5 GB` account SQLite storage, `1 GB` per object,
  and `2 MiB` key/value payloads.
- Object storage: `10 GB`, no object-count cap, `1 million` Class A
  operations per month, `10 million` Class B operations per month, free egress.
- Builds: `3,000` minutes per month, `1` concurrent build, `20 minute`
  timeout, `2 vCPU`, `8 GB` memory, `20 GB` disk, `64` build environment
  variables, and `5 KB` per build environment variable.
- Logs: `200,000` events per day, `3 day` retention, `256 KB` per event.
- API tokens: `10`.
- Support tickets: `3` per day.

  artifacts are capped at `64 MiB` before compression and `10 MiB` after

  `1 million` writes, deletes, and lists per month included. Overage is `$0.50`

## Hard Caps

Paid overage should never surprise a human. Before a high-throughput test or a
production launch, set hard caps:

```sh
tovuk limit set build_minutes --period month --value 6000 --json
tovuk limit set worker_requests --period month --value 10000000 --json
tovuk limit set worker_cpu_ms --period month --value 30000000 --json
tovuk limit set static_transfer_bytes --period month --value 107374182400 --json
tovuk limit set worker_transfer_bytes --period month --value 107374182400 --json
tovuk limit set state_requests --period month --value 1000000 --json
tovuk limit set state_sqlite_rows_written --period month --value 50000000 --json
tovuk limit set object_storage_class_a_operations --period month --value 1000000 --json
```

Tovuk reports prices in API JSON as USD micro-units. `1,000,000` means `$1.00`.
`tovuk usage --json` reports the same unit in `billingEstimate`.

The live API catalog is the source of truth for current limits and prices.
