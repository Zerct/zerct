---
title: "Deploy"
description: "How Tovuk deploys Rust workers and frontends."
---

Tovuk uses a small project contract so humans and agents can deploy without
guessing.

## Flow

1. Login with GitHub or Google.
2. Run `tovuk doctor --json`.
3. Run `tovuk preview` for local verification.
4. Run `tovuk deploy --wait --json`.
5. Tovuk queues the build, runs checks, and verifies the health route for Rust
   workers.
6. Tovuk exposes the service on a `tovuk.app` deployment hostname.

For worker-static repos, run `tovuk deploy` from the repo root. The CLI reads
the root `tovuk.toml`, builds the configured worker and frontend roots, serves
the frontend at `/`, and routes `/api/*` to the Rust worker.

## Local preview

```sh
npx tovuk preview
```

For Rust workers, preview builds the release binary and starts it with `PORT`.
For static frontends, preview builds the frontend and serves the output
directory. For worker-static services, preview builds both roots, runs the worker, and
serves the frontend with a local `/api/*` proxy.

## Runtime contract

Rust workers must listen on:

```sh
0.0.0.0:$PORT
```

Do not hardcode the port. Tovuk injects it at runtime. Static frontends do not
need a runtime process; they call Rust workers for dynamic behavior.

## Platform Resources

Use CLI commands to create runtime resources without dashboard work:

```sh
npx tovuk database create --service service_1 DB --json
npx tovuk database query --service service_1 DB "select 1" --json
npx tovuk kv create --service service_1 CACHE --json
npx tovuk queue create --service service_1 failed_jobs --json
npx tovuk queue create --service service_1 jobs --max-batch-size 10 --max-batch-timeout-seconds 5 --dead-letter-queue failed_jobs --json
npx tovuk cron create --service service_1 nightly "0 0 * * *" --json
npx tovuk durable-object create --service service_1 Room --json
npx tovuk binding create --service service_1 AUTH_SERVICE --target auth-service --json
```

## Agent-ready errors

CLI and API errors should be machine-readable:

```json
{
  "code": "missing_cargo_lock",
  "message": "Cargo.lock is required for reproducible deploys.",
  "agent_instruction": "Run cargo generate-lockfile, commit Cargo.lock, then retry."
}
```

Agents should always fix the first failed check or first actionable log line,
then rerun doctor before redeploying. After a failed build, start with:

```sh
npx tovuk logs --build <build_id> --json
```
