## Week of June 1, 2026

### New

- **Deploy history and cancellation.** Inspect and stop in-flight deploys from
  the CLI with `tovuk deploy list`, `tovuk deploy show <deploy_id>`, and
  `tovuk deploy cancel <deploy_id>`. See the
  [AI agent deploy workflow](/agents#deploy-workflow).
- **Read-only deploy planning with `--dry-run`.** Preview a deploy before
  running it with `tovuk deploy --dry-run`, which now returns warnings,
  enabled meters, plan limits, object storage meter coverage, and a
  `billingEstimate` so agents can audit cost and capability impact before
  shipping. The standalone `tovuk plan` command has been removed in favor of
  this flag. See the [AI agent deploy workflow](/agents#deploy-workflow).
- **Account management from the CLI.** Inspect and update your account with
  `tovuk account show`, `tovuk account update --handle <handle>
  --display-name "<name>"`, and `tovuk account activity --json` for a
  structured activity feed. See the [AI agent deploy workflow](/agents#deploy-workflow).
- **Abuse reporting and lifecycle commands.** Report, appeal, and track abuse
  cases from the CLI with `tovuk abuse report`, `tovuk abuse list`, and
  `tovuk abuse appeal <case_id>`, with operator-side `quarantine`, `resolve`,
  `reject`, and `release` actions for confirmed cases. See the
  [Abuse reporting workflow](/abuse).
- **Multipart object storage uploads.** `tovuk storage upload` now switches
  to multipart transfer automatically for large files, so agents can ship
  big assets without hitting single-request limits. See
  [Object Storage](/reference/storage).
- **Usage cap notifications.** `tovuk limits set` now accepts
  `--notify-at-percent` so you can get an early warning before a meter hits
  its hard cap. See [Deployment Limits and Guardrails](/reference/limits).
- **Persistent JSON output mode.** Set `TOVUK_OUTPUT=json` for a session (or
  pass `--output json`) instead of repeating `--json` on every command.
  Useful for agent and CI environments that always want structured output.
  See [Packages](/reference/packages).
- **Full-stack `shape-store` example.** A new end-to-end Rust worker plus
  TanStack frontend example ships in the `tovuk` crate, showing the
  one-URL full-stack deploy pattern with the latest service contract. See
  [Templates](/templates).
- **Dark mode by default.** The docs site now defaults to dark mode.

### Updates

- **`tovuk doctor` is now `tovuk check`.** The command name aligns with how
  agents and humans actually describe it. The behavior, flags, and JSON
  shape are unchanged. See the [AI agent deploy workflow](/agents#deploy-workflow).
- **`tovuk database` is now `tovuk sqlite`.** Query, backup, and restore
  commands moved to `tovuk sqlite query`, `tovuk sqlite backup create`, and
  `tovuk sqlite backup restore` to match the underlying product. See
  [SQLite](/reference/sqlite).
- **Explicit service capabilities are required.** `tovuk.toml` now requires
  the `[capabilities]` table on every service so enabled and disabled
  surfaces are visible before deploy. See [tovuk.toml](/reference/project-contract).
- **Service inspect retired in favor of `service show`.** `tovuk service show`
  returns the full service snapshot agents previously read from
  `service inspect`. See [Service resources](/reference/resources).
- **Service is validated before re-prompting auth.** The CLI now checks the
  `--service` value first, so a typo no longer triggers an unnecessary
  login flow.
- **Friendlier `tovuk help` output.** Help text now lists commands in the
  order agents use them and includes JSON-mode hints.
- **Missing service errors link to docs.** When a command references a
  service that does not exist, the error now points to the relevant
  reference page so you can fix it in one step. See [Service resources](/reference/resources).

### Fixes

- **Local dev port conflicts are explicit.** `tovuk dev --json` now returns
  `ok: false` plus `dev.port_statuses[].owner` when a planned worker or
  frontend port is already occupied and the PID/command can be detected.
  Human-readable `tovuk dev` prints the owner row and exits before launching
  child processes, so agents do not smoke-test a stale worker by accident. See
  [Packages](/reference/packages).
- **Homebrew install guidance.** Install instructions now show the correct
  tap and formula path. See [Packages](/reference/packages).
- **Object storage meters in deploy dry run.** Object storage usage meters
  now appear in `tovuk deploy --dry-run` output alongside other priced
  meters, so estimates match the post-deploy bill.

## Week of May 25, 2026

### New

- **Tovuk is the new name for the platform.** The CLI, packages, and Homebrew
  formula now ship under `tovuk`. Install with `npm install -g tovuk`,
  `brew tap tovuk/tovuk https://github.com/tovuk/tovuk && brew install tovuk`,
  `pipx install tovuk`, or `cargo install tovuk`. See [Packages](/reference/packages).
- **One-URL full-stack deploys.** Ship a Rust worker and static frontend
  from one repo with a single root `tovuk.toml`. Run
  `tovuk deploy --wait --json` to get one `*.tovuk.app` URL serving static
  assets at `/` and the worker at `/api/*`. See [Rust Workers](/reference/workers).
- **Project templates and local checks.** Scaffold a Rust API, TanStack static
  frontend, or full-stack project with `tovuk new`, then run
  `tovuk check` to test locally before deploying. See
  [Templates](/templates).
- **Custom domain verification.** Verify and connect custom domains from the
  CLI without leaving your terminal. See [Custom Domains](/reference/domains).
- **Agent and deploy inspection commands.** `service show` and `logs` commands
  return structured JSON for service, build, and deploy state so agents can
  debug failed deploys end to end. See [Logs and Builds](/reference/logs-builds).
- **Homebrew tap.** Install the CLI on macOS with
  `brew tap tovuk/tovuk https://github.com/tovuk/tovuk && brew install tovuk`.
  See [Packages](/reference/packages).
- **Structured support tickets from the CLI.** Open, list, and resolve tickets
  with `tovuk support` and attach service, build, deploy, and log context for
  faster triage. See the [Support ticket workflow](/support#support-workflow).
- **Agent-ready object storage.** Upload, list, download, share, and delete service
  files and media with `tovuk storage` and JSON responses. See
  [Object Storage](/reference/storage).
- **Usage cost estimates.** `tovuk usage --json` now includes
  `billingEstimate.lineItems` so agents can see current-month overage estimates
  before load tests or large uploads. See [Pricing and Usage Limits](/pricing).

### Updates

- **Compact service status.** `tovuk service status <service> --json` returns
  top-level `ok`, `url`, and `agent_instruction` fields, plus runtime status,
  latest deploy, latest build, URL, and `live` boolean for quick post-deploy
  checks. Use `service show` when agents need the full resource, usage,
  billing, log, env, and domain snapshot.
- **Explicit service capabilities.** `tovuk.toml` now uses a required
  `[capabilities]` table so agents can see enabled and disabled service
  surfaces before deploy. See [tovuk.toml](/reference/project-contract).
- **Deploy `--wait` mode in SDKs.** The npm, PyPI, and Cargo SDKs now wait for
  builds to finish and stream a final status, with concurrent waits for
  full-stack workspaces. See [Packages](/reference/packages).
- **Preflight deploy limits in SDKs.** Plan-limit checks now run before a
  deploy starts, returning a Stripe checkout link via `tovuk billing checkout`
  when an upgrade is needed. See
  [Deployment Limits and Guardrails](/reference/limits).
- **Actionable check feedback.** `tovuk check` now returns a concrete
  `agent_instruction` for every failed check and `checks[].status` in JSON so
  agents can filter failures directly. See the
  [AI agent deploy workflow](/agents#deploy-workflow).
- **Frontend checks install dev dependencies.** Generated npm frontend check
  commands now use `npm ci --include=dev` so TypeScript checks keep dev-only
  type packages even when the environment is production-biased.
- **Improved workspace check UX.** Faster checks and clearer output for
  full-stack workspaces. See the [AI agent deploy workflow](/agents#deploy-workflow).
- **Inline CLI flag values.** Flags now accept inline values
  (`--service=service_1`) alongside the existing space-separated form. See
  [Packages](/reference/packages).
- **CLIs are aligned across npm, PyPI, and Cargo.** The same commands,
  flags, and JSON responses are available from every package. See
  [Packages](/reference/packages).

### Fixes

- **Deploy wait fails on failed builds.** `tovuk deploy --wait` now exits with
  an agent-readable error when the remote build ends as `failed` or `canceled`,
  pointing agents to `tovuk logs --build <build_id> --limit 100 --json`.
- **Clearer deploy wait summary.** `tovuk deploy --wait` now streams the final
  build status without repeating `queued <job>` after a successful wait.
- **Reject unknown CLI flags.** The CLI now errors clearly instead of silently
  ignoring typos. See [Packages](/reference/packages).
- **Stable npm signature verification.** Signature checks no longer fail
  intermittently during scoped publishes.
- **Fixed broken agent readiness link in `llms.txt`.** See the
  [AI agent deploy workflow](/agents#deploy-workflow).
